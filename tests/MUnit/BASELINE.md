## What each closure gate proves — and what it does not (AUDIT02/P5.1)

Added after an audit found the close-out sequence treating a change-detector as
evidence of numerical correctness. Run them together with `make closure`; the
MUnit suite is run separately because it is slow.

| gate | proves | does **not** prove |
|---|---|---|
| `tools/snapshot_paper_numbers.py --check` | the two manuscripts' number-bearing lines are byte-identical to a committed snapshot **of those same `.tex` files** | that any number is *correct*. It is a manuscript change-detector. It would happily pin a wrong value, and did: `ZIP = 1600` sat behind a green gate until corrected to `10016` |
| `tools/check_glossary_sync.sh` | our `GOVERNANCE/GLOSSARY.md` body matches the sibling `series-deconvolution` copy | that the **code** conforms to the glossary. It compares two documents. A retired term can live on in the engine, or a citation can dangle, with this green — currently true of the `src/causal/CausalBool.m` citation at `GLOSSARY.md:236` |
| `tools/check_single_engine.sh` | `createRepertoires` and `runDynamic` have exactly one non-archived definition site | that the single engine is *correct*, only that a second copy has not reappeared |
| `make verify-paper` | **a manuscript number equals what its producer computes.** The only member that reconciles a value to its source | coverage: 3 of 8 artefact groups are COVERED, 5 remain PENDING |
| `zsh tests/MUnit/run-tests.sh --all` | the suite ledger, judged elementwise against this file | anything about the bio pipeline or the paper producers, which it does not exercise |

The load-bearing member is `verify-paper`. A close-out that omits it has checked
that the manuscripts did not change, not that they are right.
