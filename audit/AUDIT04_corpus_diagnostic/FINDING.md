# The R4/R5 corpus blocker, decomposed

**Status:** measurement only. **Date:** 2026-09-05 (AUDIT04 Phase 5).
**Producer:** `audit/AUDIT04_corpus_diagnostic/classify_corpus_nodes.py` —
every number below is regenerated by running it; none is typed by hand.

**No description length is recomputed here and no bio number is regenerated.**
The author gate on R4 stands. This exists so that the decision behind that gate
is made against a decomposition rather than against a single aggregate.

---

## 1. The claim under test

`audit/AUDIT03_PLAN.md` R3.b:

> `76.4%` of corpus nodes (3,977 of 5,204) carry a label outside the twelve, and
> **their formulas are multi-valued threshold expressions already recorded
> unevaluable** (AUDIT02/H). **No description length of any kind reaches them.**

**The denominator reproduces exactly. The characterisation does not.**

```
networks with cm+gates+nodes : 170     (record: 170)
nodes over those networks    : 5,204   (record: 5,204)
outside the twelve families  : 3,977   (record: 3,977 = 76.4%)   76.4%
```

The aggregate is right. What it contains is not what the sentence says.

---

## 2. The decomposition

A node was classified by **attempting the thing claimed impossible** — building
its truth table over all 2^k assignments — and by syntax only where evaluation
is not possible.

| category | nodes | share |
|---|---|---|
| **`derivable`** — full truth table **built** by evaluation | **1,181** | 29.7 % |
| **`identity`** — `y = x`, in-degree 1, logic is the input's own name | **762** | 19.2 % |
| `no-gate-entry` — listed in `nodes`, absent from `gates` | 578 | 14.5 % |
| **`multi-valued`** — level references (`Pu1:2`, `ATM:1`) | **510** | 12.8 % |
| **`threshold`** — `GEQ`/`LEQ`/`LT`/`EQ` against a free `theta` | **407** | 10.2 % |
| `undeclared-vars` — formula names variables absent from its own `inputs` | 294 | 7.4 % |
| `source` — in-degree 0; no update function exists to derive | 245 | 6.2 % |

Rolled up:

| | nodes | of the 3,977 |
|---|---|---|
| **Derivable today** (table built, or `y = x`) | **1,943** | **48.9 %** |
| **Genuinely blocked** (multi-valued or free threshold) | **917** | 23.1 % |
| No update function to derive (source, or absent from `gates`) | 823 | 20.7 % |
| Data defect (formula references undeclared variables) | 294 | 7.4 % |

> **The blocker is `917 / 5,204` = 17.6 % of the corpus, not 76.4 %.**
> Just under half of the nodes recorded as having "no derivable Boolean truth
> table" have one, and it was obtained by building it.

`(PLCG | ICOS) & !LAG3`, `DnaA & !CtrA` and
`AND(OR(TH1e, TBET), NOT(GATA3))` are ordinary Boolean formulae. They were
counted as blocked because they carry the gate **label** `CUSTOM`, and the label
was read as a statement about evaluability. It is not one.

## 3. The two blocking mechanisms are disjoint, and each belongs to one source

| source | multi-valued | threshold | derivable |
|---|---|---|---|
| `published` (GINsim) | **510** | 0 | 1,684 |
| `BioModels` | 0 | **407** | 230 |
| Literature / CellCollective / RegulonDB | 0 | 0 | 29 |

Perfect separation, and it is structural rather than coincidental:

- Every one of the **68** files carrying multi-valued nodes is `ginsim_*` —
  **68 of 68**, GINML-derived.
- Every one of the **30** files carrying threshold nodes is `MODEL*`, BioModels.

**So the multi-valued half of the blocker is the GINML binarisation defect this
audit surfaced in AUDIT03-C** (582 of 5,882 GINML nodes multi-valued across 108
of 178 files, 304 carrying discarded higher-level rules). It is not a new gate
family and it does not need one. The two halves are separate problems with
separate remedies and should stop being quoted as one number.

---

## 4. Two findings that were not being counted at all

**578 nodes are listed in `nodes` but have no entry in `gates`.** They are not
"outside the twelve families" in any meaningful sense — there is no label to be
outside. This is also the gap between two of the three node counts in
circulation for this corpus (5,204 vs 4,626).

**294 nodes have a formula naming variables absent from their own `inputs`
list.** The formula and the declared in-degree disagree, so any description
length charged over `inputs` prices a different function from the one the
formula describes. This is a data-integrity defect, it is silent, and it is
independent of the multi-valued question.

## 6. What this does and does not license

**Does not:** recompute any description length, regenerate any bio number, or
reopen R4. The author gate stands.

**Does:** replace one aggregate with a decomposition, so that the next decision
is taken against the right quantity. Concretely, three of the four buckets have
different remedies, and only one of them is research-shaped:

1. **1,943 derivable** — an engineering task: the loader classifies by label
   where it could evaluate.
2. **510 multi-valued** — already diagnosed; it is GINML binarisation, and
   `GINMLParser` now records `is_multivalued`, `multivalued_nodes` and
   `discarded_value_rules` per model.
3. **294 undeclared-vars** — a corpus repair, independent of the above.
4. **407 threshold** — the genuinely open one: a `GEQ(x, theta)` with `theta`
   free has no Boolean reading until `theta` is fixed, and fixing it is a
   modelling decision, not a parsing one.

## Method, and where it is weak

- Classification prefers **evaluation over pattern-matching**: `derivable` means
  a table was built, not that a regex matched.
- Two Boolean spellings are handled because the corpus uses both — infix
  (`A & !B`) and function-call (`AND(A, NOT(B))`). **An earlier pass of this
  analysis handled only the first and mis-scored 203 evaluable nodes**, and a
  `!` → ` not ` substitution left a leading space that turned 376 more into
  false failures. Both were my errors, found by running the classifier rather
  than reading it, and both are fixed in the committed producer.
- Nodes of in-degree > 16 would not have their table built; **none occurs**, so
  the cap is not currently load-bearing.
- The classifier refuses on an empty corpus rather than reporting a clean sheet.
