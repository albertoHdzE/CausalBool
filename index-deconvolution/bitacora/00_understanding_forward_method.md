# Bitacora 00 — Understanding the Forward Method

Date: 2026-07-09
Status: complete and verified

## Purpose

This entry records the precise understanding of the CausalBool forward method
that the deconvolution inverts. Every claim here is grounded in the source
files of the repository and, where a numerical fact is asserted, in an
executed cross-check.

## The forward transform

The CausalBool method represents a synchronous Boolean network by two objects:

- a connectivity (adjacency) matrix `C`, of size `n x n`, with `C[k][i] = 1`
  if and only if node `i` feeds node `k` (row `k` lists the inputs of node
  `k`);
- a dynamics list `D`, giving one Boolean gate per node, drawn from the twelve
  canonical families AND, OR, XOR, NAND, NOR, XNOR, NOT, IMPLIES, NIMPLIES,
  MAJORITY, KOFN, CANALISING.

The forward transform enumerates the `2^n` input vectors in a fixed order and,
for each node `k`, applies the node gate to the sub-vector of connected inputs.
The result is the **output repertoire**: a `2^n x n` binary matrix whose column
`k` is the truth table of node `k` over all inputs, and whose row `x` is the
synchronous next-state vector of the network for input `x`.

The canonical reference implementation is
`papers/method/code/lib/CausalBoolCore.wl` (function
`CreateRepertoiresDispatch`) and the packaged gate semantics are in
`src/Packages/Integration/Gates.m` (function `ApplyGate`).

## Ordering convention

Two orderings appear in the programme, related by the bit-reversal involution
`phi`. The companion code and this deconvolution project both use **LSB-first**:
for decimal `x` the input vector `v` has `v[i] = (x >> i) & 1`, so `v[0]` is the
least significant bit. This reproduces the Wolfram expression
`Reverse[IntegerDigits[x, 2, n]]`. Connected input positions are taken in
ascending order before the gate is applied, reproducing
`input[[Sort[Flatten[Position[cm[[node]], 1]]]]]`.

The deconvolution is, in principle, ordering-agnostic (the essential variables
of a Boolean function and the function itself do not depend on how inputs are
enumerated). The convention only fixes the numeric labels of the recovered
connectivity. We fix LSB-first so that recovered networks can be replayed by
the canonical Wolfram reference without any remapping.

## The pivots and sumandos structure

The AND derivation (`papers/method/derivations/02_cb_and.pdf`, `.tex`)
establishes the structural fact on which the deconvolution rests. For a node
`k` with connected set `I_c`:

- the **pivot** `P = sum over i in I_c of 2^(i-1)` is the fixed decimal
  contribution of the connected nodes;
- the **offset family** (the *sumandos*, denoted `Omega`) is generated by the
  disconnected nodes `I_nc`, whose states shift the index without changing the
  membership condition.

For AND the one-set (indices where the output equals 1) is exactly
`{ j : v_i(j) = 1 for all i in I_c }`. The connected bits are pinned; the
disconnected bits range freely. The OR derivation gives the dual statement:
the zero-set pins the connected bits to 0.

The consequence, which is the seed of the whole deconvolution, is:

> A disconnected node lies entirely in the free offset dimension. Perturbing
> it moves the index within the offset family `Omega` and never changes the
> output. A connected node participates in the membership condition;
> perturbing it can change the output.

This is the exact, deterministic analogue of the perturbation step in the
algorithmic-information deconvolution of Zenil and colleagues
(`doc/Zenil-Papers/AICalculusCausalDiscovery-arxiv.pdf`,
`imp-causalNet-paper/papers/ACausalDeconvolutionNetGeneMecha.pdf`). There the
perturbation is measured against an approximate complexity (BDM); here it is
measured against the exact output column, so no approximation is involved.

## Factorisation over nodes

Because column `k` of the repertoire depends only on node `k` and its connected
inputs, the forward transform factorises over nodes:

    repertoire column k  =  f_k( v restricted to I_c^k )

This factorisation is the reason the inverse problem is tractable and exact:
the deconvolution of the whole network reduces to `n` independent single-column
problems. This is developed in Bitacora 01.

## Verified equivalence of the Python forward model

To obtain a fast, testable, self-contained pipeline, the forward method is
re-implemented in Python (`src/causalbool.py`) following the LSB-first
convention above. Equivalence with the canonical Wolfram reference is not
assumed but **proven**: the cross-check `crosscheck/wolfram_equivalence.wl`
recomputes the repertoire of 45 generated networks (sizes 6, 7, 8; the eleven
gates supported by `CausalBoolCore.wl`) with `CreateRepertoiresDispatch` and
compares byte for byte against the Python repertoires.

Result: **45 / 45 cases identical**. The Python forward model is equivalent to
the canonical reference on the tested family. CANALISING, absent from
`CausalBoolCore.wl`, is validated separately through the Wolfram `Gates.m`
semantics that the Python `apply_gate` reproduces verbatim.
