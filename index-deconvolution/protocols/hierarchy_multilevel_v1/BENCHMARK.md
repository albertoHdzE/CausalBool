# Exposed-data feasibility design

## 1. Fixed cases, references and job counts

Use exactly 96 saved strings from accepted `search-confirm-v2-r1`:
confirmation F01..F12 x base lengths {1024,4096} x replicates {3000,3001}
x {base,ragged}. CASES.json fixes IDs, actual n, input hash and saved references.
Decode the retained raw archive to obtain each input; do not call a generator.
Validate archive/input hashes and actual n before use. All these inputs are
previously exposed; do not label any result confirmation or held-out performance.

After implementation lock, run A0 independently once per input: 96 jobs.
Its archive bytes, config identity and timing-stripped deterministic scientific
fields must reproduce the saved k=1 record. Any unexplained mismatch blocks the
remaining queue. Validate all 96 baseline jobs before augmentation begins.

Then execute A1, A2, A3 augmentation independently on each input: 288 jobs, each
with its own dictionary/search/caches and the saved, parent-verified A0 archive.
Order is CASES.json order, then A1,A2,A3. At most two active children. Total new
jobs: 384 (96 baseline + 288 augmentation); 288 composite selection records are
derived, not another set of encoder jobs. Keep separate intended/available counts
for jobs, selected archives, traces, view records and imported references.

Read the nine baseline archives from the accepted run; verify/decode their bytes
and reconstruct the minimum by the existing portfolio rule, including ties.
There are 864 imported constituent records and 96 derived portfolio references.
They are not new jobs. Do not present their old timing as a new same-environment
timing comparison. Include pair_grammar explicitly in all descriptive tables.

## 2. Before-lock engineering cases

Fixtures are engineering witnesses, never part of the 96-case endpoint. Limit
to 32 distinct input strings up to 4,099 bits, declared with exact constructions
and hashes before running the fixture suite. Every unique input counts, including
randomized-test inputs; do not hide a corpus sweep as a property test. Tests may
reuse these strings under several tiny cap/config/status fixtures. Any pseudorandom
fixture uses local seed 62001 and records its generated bytes, with no access to
reserved namespaces. At minimum cover:

- Empty and short inputs, single-symbol vocabularies, odd symbol counts, all
  phases, ragged tails at each level, and a width larger than the input.
- Alternating words and a fixed-count permutation; nested A/B phrases; a
  recursively substituted binary sequence (e.g. 0->01, 1->10). Mark forced
  grouping separately from actual reuse. These fixtures do not prove fractality.
- Random controls and all-distinct structured counter words, including a path
  stopped for saturation while its dictionary retains recognizable structure.
- An exact gap template and one with exceptions below/above the 64-flip limit.
- A case where shorter tokens lose after dictionary/header cost; duplicate
  proposals; length ties; graph-rule/depth rejection; branch stop labels.
- Symbol relabelling followed by canonical first-appearance normalization yields
  identical proposals/bytes. Without recanonicalization, numerical tie order is
  not promised invariant. A3 restricted to level 1 must equal A2; A2 restricted
  to width 8 must equal A1, including deterministic traces.
- Real child watchdog exercised with tiny fixture limits (label these as fixture
  limits, not observed 30 s/1 GiB study breaches); parent retains baseline through
  child termination. Check incomplete atomic writes, resume corruption, missing
  rows and INVALID-over-INCOMPLETE through the entire reporting path.

Use independent hand expectations for small cases; do not make the implementation
its own oracle. Decoder round trips and lossless span coverage are mandatory.
The 32-input bound applies to the new experimental fixtures, not the unchanged
existing-owner regression suites required by ACCEPTANCE section 3.

## 3. Descriptive analysis, fixed before the benchmark

For input x define saving(A,B)=(bits(B)-bits(A))/len(x), using complete archive
bytes times 8 and the actual ragged length. Average base/ragged within replicate,
then replicates within family/length cell, then the 24 cells equally. Retain all
per-string, per-pair, per-cell and aggregate values. No bootstrap or inference.

Report A1-A0 (single-width abstraction), A2-A1 (additional word widths), A3-A2
(additional levels), and each composite against A0, pair_grammar and portfolio.
Count better/tie/worse strings and cells, successful proposal selections, fallback
statuses, actual runtime/RSS, attempted/evaluated views and cost by rule kind.
Report physical study execution totals and baseline-plus-augmentation attributed
deployment costs separately. Do not claim speedup because the token stream shrank.

All arms have common upper limits, not forced equal work. Width/depth comparisons
measure these specified algorithms, including their extra eligible proposals and
cost; they do not isolate representation quality at identical realized compute.

If any required arm is unavailable, do not compute the declared aggregate on a
reduced population. Descriptive available-case tables may be shown with explicit
denominators under an INCOMPLETE overall status. Invalid evidence wins over missing
evidence and disables recommendation logic. A legitimate fallback is included at
its retained full archive cost and disclosed in the workload completion counts.

Completed engineering verdict: VALID_COMPLETE, INCOMPLETE or INVALID. Conditional
exploratory recommendation: NO_RETAINED_GAIN if A3 never beats A0 on the 96
strings; NO_ADDED_LEVEL_GAIN if A3 beats A0 somewhere but never beats A2;
LEVEL_GAIN_OBSERVED otherwise. These labels guide a next design; none means
statistical superiority, generalization, causality or adoption. Always report
A2 gains even if A3 adds none. Synthetic fixture wins cannot trigger these labels.

## 4. Deliverables and stopping

Produce an auditable source/parameter lock and snapshot; preservation manifests;
declared fixture inputs; tests/guards/attempt and resource ledgers; intended jobs;
reference validation; per-job atomic rows/archives; baseline reproduction gate;
per-view proposal and gap records; status-aware tables and REPORT/DECISION;
independent read-only arithmetic audit; notebook 21 and guarded execution evidence;
HANDOFF including all disclosures and a recommendation for M2 or a documented stop.

Notebook 21 shows saved examples and width/level maps only; no inference, fitting,
generator, new BDM calculation or subprocess. Reuse the reviewed artifact-only
guard, decoder/ledger allowlist, blocked result writes and coalesced stream-output
comparison. Execute once successfully from repo root and notebook directory,
retaining earlier failures when fixes require another attempt. Explain displayed
examples as illustrations, not selected evidence of average performance.

Do not start M2/M3/M4, change caps, add widths/levels, search for better fixtures,
combine k=4, change TILE or rewrite historical outputs after seeing results.
