# HID-v1 acceptance and supervisor review — normative annex

Version 1, 2026-10-01. The developer completes this checklist with evidence paths;
the supervising session will independently assess it after the user returns.

## A1. Hard rejection conditions

Any of these prevents engineering acceptance, regardless of impressive plots:

- The decoder needs original data, a hidden dictionary, generator metadata, or a
  Python program that is not charged/transmitted by the specified format.
- An archive fails exact decoding or a measured length differs from actual bytes.
- Data are silently dropped, padded without recoverable length, reordered without
  transmission, or made accessible to inference through case names/side channels.
- The proposed method, comparator, or test set is modified after seeing held-out
  performance and the change is concealed.
- Failures, timeouts, nulls, or losing families are omitted from a headline result.
- Baseline headers are stripped while ours are retained differently, or an ASCII
  input compressor is compared against our packed-bit input without disclosure.
- Tests are removed/loosened to fit the output; expected values are generated by the
  same implementation being tested without an independent invariant/reference.
- Existing unrelated edits are reverted, shared owners duplicated, or old results
  overwritten without retaining their provenance.

Unsupported scientific interpretations prevent scientific acceptance even when the
implementation is sound: K estimation, unique causal recovery, universal discovery,
prediction from full-string compression, or priority claims without evidence.

## A2. Required tests and verification

### Codec and decoder

- Literal round-trip all 2047 strings of lengths 0..10.
- Every individual baseline round-trip all 511 strings of lengths 0..8, with empty
  input following the literal convention. Tests account for external-library format
  bytes under the recorded version; do not hardcode unstable compressed bytes.
- Hand-derived golden byte fixtures in the wire annex and additional fixtures for
  each opcode, multi-byte U, enum ranks, overlap, polarity, and ragged domains.
- Independent tiny semantic interpreter versus production wire decoder for AP,
  schema, concat, repeat, patch, and transform compositions.
- Separate-process decoder run on a collection of archives with inference modules,
  corpus metadata, and original strings unavailable to that process. The test
  harness may retain originals outside it to compare the returned strings.
- Targeted malformed archives: unknown opcode/mode, forward reference, cycle
  attempt, unreachable rules, malformed U, invalid counts/ranks/masks, nonzero
  padding, trailing data, truncated payload, out-of-range correction, impossible
  Markov queues, decompression overrun, and resource-limit breach.
- Valid data-byte mutations may decode to another string: do not assert that a
  lossless codec without a checksum detects all corruption.
- Byte ledgers sum exactly to archive length, including U lengths, envelope,
  individual packed fields, and padding. Costs must be derived from serialized
  bytes; proxy estimates may be logged only as proposal heuristics.

### Search and scientific invariants

- Full search and five ablations round-trip every string of lengths 0..8 and a
  seeded larger suite. They all retain the literal fallback and enforce caps.
- Same input/config in fresh processes with different PYTHONHASHSEED values gives
  identical completed archive bytes and deterministic counters. Exclude measured
  runtime/RSS from byte-for-byte report equality.
- Inference modules do not import corpus/benchmark/reporting, and their API has no
  family/seed/truth arguments. Renaming input files cannot change completed results.
- Exact period discovery handles primitive periods beyond 12, incomplete final
  copies, one-bit strings, constants, and arbitrary prefix phases.
- Joint reuse is demonstrated on an automatically inferred example. Do not insert
  a hand-authored winning model through a case-specific branch.
- Schema reconstruction agrees with explicit don't-care fillings, including a
  don't-care on a participating coordinate and a clipped non-power-of-two domain.
- The A64 zero support has no Hamming-one edge in its original six-bit addresses;
  that fact is kept separate from a possible compact complementary representation.
- A transmitted permutation/order distinguishes two macro arrangements, while a
  regular repeated order may obtain a shorter code. No assertion requires every
  permutation to have a distinct total length.
- Fixed rotations/complements/reversal are exactly invertible by the decoder.
  Do not assert that all archive lengths must be invariant: this is a fixed code,
  not true K or an invariant optimal code.
- Tiny bounded-oracle results report their exact language, bounds, grammar-only
  minima, raw-inclusive minima, and gaps. Test a case where repetition changes the
  winner, so the oracle test cannot pass solely because literal always wins.

### Shared owner and historical notebook

- Existing 91 description-length tests remain; newly added tests cover invalid
  inputs/policies/steps and recursive full coverage. Record actual final count.
- Explicit valid historical CTM/BDM scores remain numerically unchanged.
- Empty/short data policies and bool/integer versus float parameters are tested.
- Builder 15 and notebook 15 agree; all code cells execute with zero error outputs.
  Notebook 16 and its builder likewise reproduce the saved report data.
- Preserve historical audit JSON; regenerated audit output uses a new path.
- Run repository lint on every changed/new production Python file using the existing
  ruff configuration. Fix violations without adding blanket ignores.
- Run `tools/check_core_index.sh`, relevant owner/manifest guards, and the targeted
  tests. Run the root `tests/analysis` suite once for shared-interface regression
  coverage. Investigate new failures; distinguish reproducible pre-existing failures
  by running the relevant test against the saved starting inputs, without resetting
  the user's tree. Do not promise the unrelated full Wolfram suite was run.

### Experiments and analysis

- Freeze manifest predates generation/scoring of the confirmation/transfer corpus.
- Expected case/method counts match actual counts, including explicit error,
  timeout, and not_run statuses. Do not equate an absent row with zero size.
- Every successful archive matches recorded SHA-256 and its source input on decode.
- Bootstrap preserves base/ragged pairs and paired methods; equal weights and fixed
  seed match the benchmark annex. Hand-check a small artificial result table whose
  sign and aggregate are known; test that missing baseline results block a positive
  scientific verdict.
- Primary comparison uses the entire fixed baseline portfolio; selected-baseline
  IDs and archive lengths agree with constituent rows. Portfolio timing is summed
  work, not a free oracle's runtime.
- BDM rank adaptation runs symmetrically on every null row; p is never zero and
  ties are inclusive. Explain the null's scope on Markov sequences.
- Resume rejects mismatched source/config/input hashes, skips intact completed
  rows, and reproduces the same final data after a deliberately interrupted pilot.
- Wrong decode, incomplete run, and inconclusive science have distinguishable exit
  codes/status fields; scientific disappointment never causes fabricated success.

## A3. Quality requirements

Keep the core small and readable. Type public interfaces; use immutable rule
records and explicit validation exceptions. Avoid global mutable RNGs, import-time
experiments, hard-coded absolute user paths, unbounded exhaustive substring scans,
and catch-all exception handling that converts a bug into a successful result.

Implement analysis once. Notebooks import or read saved artefacts; they do not
reimplement inference, cost formulas, or result selection. Use integer widths and
actual serialization for all code lengths. Numeric score comparisons, if any,
have declared tolerances. Codec correctness tests do not depend on timing thresholds.

Document algorithmic complexity and measured caps, including where the current
schema-cover routine is exponential or greedy. “Best found under budget” must be
the default language. Do not rename an approximation to imply exact minimisation.

Package test data and a small smoke run so a fresh reviewer can exercise all modes
without rerunning the full study. Include a command that verifies the stored full
study read-only. Do not require internet access for reproduction once the current
environment and retained local artefacts exist.

## A4. HANDOFF.md — required order and content

The developer's final handoff must contain:

1. **Outcome:** engineering status; scientific verdict; primary effect and interval;
   whether confirmation and transfer completed. State negative results plainly.
2. **Paths:** protocol version/hash, run ID, freeze, source manifest, report, notebook,
   result JSONL, archives, verification, and claim ledger.
3. **Commands:** exact interpreter and working directory; selfcheck, tests, read-only
   stored-run verify, one encode/decode example, and full resume/reproduction commands.
4. **Changes:** files changed/created and their purpose; narrow shared-owner changes;
   any deviations, invalidated runs, new dependencies, and pre-existing failures.
5. **Evidence table:** pass/fail/not-run for every H0–H5 gate, test counts, lint/guard
   results, round-trip count, timeout/error counts, and resource usage.
6. **Scientific table:** primary aggregate, every family/size, all five ablations,
   transfer, statistical controls, and BDM diagnostics. Distinguish uncertainty
   from absence of an effect and absence of evidence from proven randomness.
7. **Representative artefacts:** one automatically inferred success, one baseline
   loss, one fallback/noise case, and a tiny oracle case, each with input/archive
   hash, decoded equality, graph explanation, and exact byte ledger.
8. **Open issues:** what remains uncertain, what failed, what was not implemented,
   and the smallest warranted next experiment. No marketing conclusion.

Also include a compact final chat response directing the user to HANDOFF.md and
explicitly stating “Ready for supervisor review” or “Incomplete; review required”.
The user needs to bring back that path and run ID, not paste thousands of result rows.

## A5. What the supervisor will independently review

The returning supervising session will inspect scope/provenance and then:

1. Recalculate lengths from retained archive bytes and decode a stratified sample,
   including losses and fallbacks, using only the independent decoder.
2. Inspect wire fields and golden fixtures for hidden information, especially order,
   model selection, parameters, boundaries, corrections, and coordinate mappings.
3. Inspect inference imports/call signatures and corpus separation for leakage.
4. Reproduce the tiny-oracle cases and selected deterministic-search runs.
5. Recompute headline aggregates/intervals from raw rows and audit omitted statuses.
6. Check ablations support the claimed component attribution, and inspect baseline
   quality, frozen choices, duplicates, timeout effects, and generalisation scope.
7. Compare builder/notebook/report claims to the claim ledger and execution evidence.

The decision will be **accept**, **accept with a narrower scientific claim**, or
**request corrections**, with explicit evidence. There is no guaranteed positive
decision and no requirement to manufacture one.
