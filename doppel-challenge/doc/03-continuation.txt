## II. The Mapping to the Phishing Problem

Your mapping is correct in spirit. The cleaner phrasing is as follows.

**The phishing problem as a hypothesis test.** The defender observes a message distribution $p$ over a phrase set $T$. The defender has in mind a *natural* distribution $q$ (the baseline frequencies of phrases in legitimate traffic). The defender decides between:

- $H_{0}$: $p=q$, the message stream is natural;
- $H_{1}$: $p\neq q$, the message stream is adversarial.

The detection rule $D_{\mathrm{KL}}(p\,\|\,q)>C$ is a one-sided likelihood-ratio test against the worst case in the alternative.

**The laboratory as a generative version of the same test.** In the Boolean network setting, the defender does not see $p$ directly. The defender sees a *repertoire* $\mu$ that has been *generated* by a network $(A, \theta)$. The natural hypothesis $H_{0}$ is the original network $(A_{0},\theta_{0})$ with its induced repertoire $\mu_{0}$. The adversarial hypothesis $H_{1}$ is any perturbed network $(A',\theta_{0})$ with $A'\in\mathcal{P}_{k}(A_{0})$ and its induced repertoire $\mu_{A'}$. The detection statistic is the same $D_{\mathrm{KL}}(\mu_{A'}\,\|\,\mu_{0})$, and the alarm threshold is the same $C$.

The mapping is therefore:

| Phishing problem | Boolean network laboratory |
|---|---|
| Phrase set $T$ (fixed) | Attractor support $A_{N}=\{0,1\}^{N}$ (fixed, but reachable support is much smaller) |
| Natural distribution $q$ | Natural repertoire $\mu_{0}=\mu_{A_{0},\theta_{0}}$ |
| Attacker distribution $p$ | Induced repertoire $\mu_{A'}$ |
| Per-phrase payoff $s_{i}$ | Per-attractor loss $s(x)$ |
| Alarm $D_{\mathrm{KL}}(p\,\|\,q)>C$ | Alarm $D_{\mathrm{KL}}(\mu_{A'}\,\|\,\mu_{0})>C$ |
| Attacker choice: $p\in\Delta_{\lvert T\rvert}$ | Attacker choice: $A'\in\mathcal{P}_{k}(A_{0})$ |
| Expected payoff $\sum p_{i}s_{i}$ | Expected loss $\sum_{x}\mu_{A'}(x)s(x)$ |
| Detection budget $C$ | Detection budget $C$ |

The one structural difference — and it is a meaningful one — is that the phishing attacker chooses $p$ *directly* on the simplex, whereas the laboratory attacker chooses a *generative model* $A'$ which then *induces* a repertoire. The laboratory attacker's choice is mediated by the network; the phishing attacker's is not. This makes the laboratory *harder* for the attacker in a precise sense: not every $p$ in the KL ball is reachable by a network perturbation, so the laboratory's effective attack surface is a subset of the phishing problem's attack surface.

The defender's task is correspondingly richer. The defender can:

1. Compute the marginal alarm $D_{\mathrm{KL}}(\mu_{A'}\,\|\,\mu_{0})>C$;
2. Check catalogue membership: is $\mu_{A'}$ in the precomputed $\mathcal{C}_{k}(A_{0},\theta_{0})$?
3. Check compression distance: is $\mathrm{NCD}(\mu_{A'},\mu_{0})$ above the typical within-catalogue value?
4. Check structural recovery: deconvolve $\mu_{A'}$ to obtain $\hat{A}'$ and compare to $A_{0}$ (this is the deconvolution question, properly separated).

The first three are *forward* statistics from your protocol. The fourth is a separate inverse question that the protocol's data is well-positioned to answer.

## III. The Payoff Function $s(x)$

One element you should define explicitly before the experiment: the loss function $s:\mathrm{supp}(\mu)\to\mathbb{R}_{+}$. Three choices are natural and correspond to different attacker objectives:

- **Indicator on a target set** $T\subset\{0,1\}^{N}$: $s(x)=\mathbf{1}[x\in T]$. The attacker wants to maximise the probability mass that the perturbed repertoire places on a "bad" set of states. This is the closest analog of the phishing problem's per-phrase payoff.
- **Linear functional on the state**: $s(x)=w^{\top}x$ for a defender-chosen weight $w$. The attacker wants to shift the expected state in a particular direction in $\mathbb{R}^{N}$.
- **Entropy-weighted**: $s(x)=-\log\mu_{0}(x)$. The attacker wants to drive the repertoire into low-probability regions of the natural one — i.e., to generate "rare" outputs. This is closely tied to the Kolmogorov enrichment, because rare outputs are precisely the ones with high algorithmic information content.

Whichever you pick, $s$ should be *fixed* in the laboratory (i.e. the defender's loss function is exogenous), and the attacker is then a procedure that solves:

$$\arg\max_{A'\in\mathcal{P}_{k}(A_{0})}\;\sum_{x}\mu_{A'}(x)\,s(x)\quad\text{subject to}\quad D_{\mathrm{KL}}(\mu_{A'}\,\|\,\mu_{0})\le C.$$

For small $N$ and bounded $k$, this is enumerable; the catalogue produced by your protocol *is* the data structure that solves the maximisation offline. The optimal adversarial network is the catalogue element with the highest $s$-weighted mean subject to the KL constraint.

## IV. The Kolmogorov Enrichment, Made Precise

Your (decimals, summandos) representation is a *computable compressor* for Boolean network repertoires. Its bit length $L_{\mathrm{CB}}(\mu)$ is an upper bound on the prefix Kolmogorov complexity $K(\mu)$:

$$L_{\mathrm{CB}}(\mu)\;\ge\;K(\mu)$$

with equality up to an additive constant depending on the compressor's own description length. This is in the strict spirit of AIT, and it is what makes your enrichment a genuine *complexity* measurement rather than a heuristic.

Two compression-based statistics are worth recording for every catalogue element $\mu_{A'}$:

1. **Marginal compression length** $L_{\mathrm{CB}}(\mu_{A'})$. This is the *algorithmic complexity* of the perturbed repertoire on its own. The empirical distribution of $L_{\mathrm{CB}}$ over $\mathcal{P}_{k}(A_{0})$ is a measure of how "complex" the reachable repertoires are.
2. **Normalised compression distance**
$$\mathrm{NCD}(\mu_{A'},\mu_{0})\;=\;\frac{L_{\mathrm{CB}}(\mu_{A'}\mu_{0})-\min(L_{\mathrm{CB}}(\mu_{A'}),L_{\mathrm{CB}}(\mu_{0}))}{\max(L_{\mathrm{CB}}(\mu_{A'}),L_{\mathrm{CB}}(\mu_{0}))}$$
where $\mu_{A'}\mu_{0}$ denotes the concatenation of the two repertoires in some fixed encoding. This is the Li–Bennett–Li–Vitányi universal similarity metric. It is symmetric, satisfies the triangle inequality up to an additive $O(\epsilon)$, and is *universal* in the sense that, for any computable similarity notion, there exists a compressor that makes NCD approximate it within $O(\epsilon)$.

The decisive property of NCD for your problem is that it does **not** require a common support between $\mu_{A'}$ and $\mu_{0}$. The phishing alarm $D_{\mathrm{KL}}$ does. A perturbation that *changes the support* of the repertoire — i.e., introduces new attractors or destroys old ones — is not directly comparable by KL; the support must be intersected and arbitrary choices made. NCD handles this naturally because the compressor operates on the encoded repertoire, not on the probability vectors.

You should expect, and your protocol is positioned to confirm, the following:

- For perturbations that preserve the support, NCD and KL are highly correlated.
- For perturbations that change the support, NCD picks up the change; KL does so only after support intersection (and then depends on how the intersection is defined).
- The catalogue-membership test (is $\mu_{A'}$ in $\mathcal{C}_{k}$?) and the NCD test (is NCD within a band?) are two distinct, complementary defender tools.

## V. The Theoretical Framework, Stated

The Boolean network laboratory is, formally, the following game:

- **Defender** commits to a natural network $(A_{0},\theta_{0})$, a threshold $C$, a loss $s$, and a detection rule $\mathcal{D}:\Delta_{2^{N}}\to\{0,1\}$.
- **Attacker** commits to a perturbation budget $k$ and a network $A'\in\mathcal{P}_{k}(A_{0})$.
- **Outcome**:
  - Defender observes $\mu_{A'}$ (the perturbed repertoire).
  - Defender applies $\mathcal{D}$: alarm or no alarm.
  - If no alarm, the attacker realises expected loss $\sum_{x}\mu_{A'}(x)s(x)$.
  - If alarm, the attacker realises zero (the perturbation is detected and neutralised).

The optimal defender rule, by Neyman–Pearson, is the likelihood-ratio test between $\mu_{0}$ and the worst-case $\mu_{A'}$. The marginal alarm $D_{\mathrm{KL}}(\mu_{A'}\,\|\,\mu_{0})>C$ is a *sufficient-statistic* reduction of this test for the exponential family of repertoires; it is asymptotically optimal but not exactly optimal for finite $N$.

The optimal attacker strategy, by I-projection, is the catalogue element that maximises $s$-weighted mean subject to $D_{\mathrm{KL}}\le C$. This is the *laboratory's answer* to the original question. For small $N$ and $k$, the answer is the literal argmax of the catalogue. For larger $N$, it is the argmax of a sampled catalogue.

The two open theoretical questions that your laboratory is uniquely positioned to address are:

1. **How does the geometry of $\Phi_{\theta_{0}}$ depend on $\theta_{0}$?** The Lipschitz profile of the wiring-to-behaviour operator, as a function of the gate library, is a measurable object. Your protocol measures it.
2. **Where is the support-mismatch boundary?** The fraction of perturbations in $\mathcal{P}_{k}(A_{0})$ that change the attractor support, as a function of $N$ and $k$, defines the regime in which KL is well-defined and the regime in which compression-based measures dominate. Your protocol measures it.

These are not questions you have been asked before. They are the questions your laboratory makes answerable.

## 2. Origin and Motivation

### 2.1 The Original Problem

The challenge that motivates this project is an instance of a two-player adversarial game on a probability simplex:

- A **defender** observes a stream of messages drawn from a finite phrase set $T = \{t_1, \dots, t_n\}$. The defender's baseline is a distribution $q = (q_1, \dots, q_n)$ over $T$, the empirical frequencies of phrases in legitimate traffic.
- An **attacker** selects a distribution $p = (p_1, \dots, p_n)$ over $T$ to maximise expected payoff. Each phrase $t_i$ carries a social-engineering payoff $s_i \in [0, 1]$. If a message using $t_i$ reaches a user unflagged, it succeeds with probability $s_i$. If the message is flagged or fails to convince, the payoff is zero.
- The defender runs a lightweight detector that monitors phrase frequencies. Given the baseline $q$, the defender raises an alarm when
  $$\sum_i p_i \log \frac{p_i}{q_i} \;>\; C$$
  for a constant $C$ set by the defender. The quantity $\sum_i p_i \log(p_i/q_i)$ is the Kullback–Leibler divergence $D_{\mathrm{KL}}(p \| q)$; the alarm is a one-sided test on the divergence.
- The question posed by the problem is: what distribution $p$ should the attacker choose to maximise expected payoff?

The hint in the problem is that the optimal strategy is not deterministic. The answer in the clean setting is the exponentially tilted (Gibbs) distribution
$$p_i^{(\lambda)} \;=\; q_i \,\frac{e^{\lambda s_i}}{Z(\lambda)},\qquad Z(\lambda) = \sum_j q_j e^{\lambda s_j},$$
with $\lambda > 0$ determined by the active constraint $D_{\mathrm{KL}}(p^{(\lambda)} \| q) = C$. This is the $I$-projection of the deterministic argmax policy onto the divergence ball of radius $C$.

### 2.2 Why a Laboratory Is Needed

The phishing problem is one-dimensional in a precise sense: the attacker chooses $p$ directly on the simplex, the defender compares $p$ to $q$ by a single scalar statistic, and the question is fully answered by a closed-form exponential tilt. The problem is interesting but exhausted once the formula is written down.

A laboratory is needed when the question is not *what is the optimal $p$* but rather *how does the optimal $p$ depend on the structure of the underlying mechanism that produced $q$*. In a real phishing scenario the baseline $q$ is the empirical distribution of an unknown generative process, and the attacker has structural constraints on the $p$ that can be produced. The laboratory must therefore:

1. replace the abstract simplex with a concrete, finite, enumerable state space;
2. make the generative mechanism of $q$ explicit and manipulable;
3. allow the attacker to be constrained by a generative model rather than free on the simplex;
4. provide more than one detection statistic, so that the defender's advantage from a generative-model description can be quantified.

The CausalBool project supplies each of these: it works on finite Boolean networks, recovers the generative mechanism from a repertoire, supports recomputation of repertoires in linear time, and provides a compressed (decimals, summandos) representation whose bit length is an algorithmic-complexity measurement in the strict spirit of Kolmogorov.

### 2.3 The Core Insight

The phishing problem is a 1D slice of a higher-dimensional problem. The higher-dimensional problem is: given a known generative process $M_0$ on a finite state space, a class of perturbations $\mathcal{N}(M_0)$, and a defender's loss function $s$, find the perturbation $M \in \mathcal{N}(M_0)$ that maximises the expected loss under the constraint that the induced distribution $\mu_M$ remains within a divergence ball of radius $C$ around the distribution $\mu_{M_0}$ induced by $M_0$. The phishing problem is the special case in which the generative process is degenerate (a single multinomial draw on $T$) and the perturbation class is the full simplex. The Boolean network laboratory is the case in which the generative process is a deterministic Boolean dynamical system and the perturbation class is the graph neighbourhood of the natural network.

The CausalBool machinery makes the laboratory computationally tractable. The protocol that follows defines that laboratory.

## 3. Formal Model

### 3.1 Boolean Networks

Let $N \in \mathbb{N}$ be the number of nodes. A Boolean network on $N$ nodes is a pair $(A, \theta)$ with

- $A \in \{0, 1\}^{N \times N}$ a (possibly constrained) adjacency matrix;
- $\theta = (\theta_1, \dots, \theta_N) \in \mathcal{L}^N$ where $\mathcal{L}$ is a fixed library of Boolean functions over a bounded input arity.

A node $i$ is updated at time $t+1$ according to
$$x_i(t+1) \;=\; \theta_i\!\left(\{x_j(t) : A_{ji} = 1\}\right).$$
The dynamics are synchronous. The state space is $\{0, 1\}^N$.

The adjacency matrix $A$ specifies the **wiring** of the network. The vector $\theta$ specifies the **dynamics** (the local Boolean functions at each node). The pair is a complete description of the network.

### 3.2 Attractors and Repertoires

A trajectory starting from $x_0 \in \{0, 1\}^N$ under synchronous update visits a finite sequence of states that, after a finite transient, settles into a cycle — an **attractor**. The exhaustive output repertoire of $(A, \theta)$ is the empirical distribution over the union of all attractors under a uniform draw of initial states. Formally,

$$\mu_{A,\theta}(x) \;=\; \frac{1}{2^N} \sum_{x_0 \in \{0, 1\}^N} \mathbf{1}\!\left[x \in \mathcal{A}_{(A,\theta)}(x_0)\right] \cdot \frac{1}{|\mathcal{A}_{(A,\theta)}(x_0)|},$$

where $\mathcal{A}_{(A,\theta)}(x_0)$ is the attractor reached from $x_0$. The repertoire is a probability distribution on $\{0, 1\}^N$ with finite support; the support is the set of states that lie on at least one attractor.

The attractor set and the trajectory of a state under $(A, \theta)$ are computed by the existing CausalBool routines (`compute_attractors`, `enumerate_orbits`, `count_visits`). These routines are reused unchanged.

### 3.3 The Wiring-to-Behaviour Operator

For a fixed dynamics $\theta_0$, define the **wiring-to-behaviour operator**
$$\Phi_{\theta_0} : \mathcal{A}_N \;\longrightarrow\; \Delta_{2^N}, \qquad A \;\longmapsto\; \mu_{A, \theta_0},$$
where $\mathcal{A}_N$ is the set of admissible adjacency matrices on $N$ nodes and $\Delta_{2^N}$ is the probability simplex on $\{0, 1\}^N$. The protocol in this document studies the geometry of $\Phi_{\theta_0}$ restricted to a graph-distance ball of radius $k$ around a base graph $A_0$.

The object $\Phi_{\theta_0}$ is the laboratory's central object. The optimal attacker in the laboratory is the I-projection of the loss-maximising policy onto the divergence ball intersected with the image of $\Phi_{\theta_0}$ on a graph-neighbourhood. The defender's mechanistic advantage is the difference between the divergence alarm and the catalogue-membership test in the preimage of $\Phi_{\theta_0}$.

| $\mathcal{C}_k(A_0, \theta_0)$ | Catalogue $\{\mu_{A, \theta_0} : A \in \mathcal{P}_k(A_0)\}$ |

The project memory constraint that no Shannon quantity enter CausalBool's own internal metrics is respected. The Kullback–Leibler divergence appears in this protocol solely as the alarm quantity specified by the original problem; the laboratory's own measurements are algorithmic (compressed length, normalised compression distance, support distance).

---

## 4. Perturbation Class

### 4.1 Why Connectivity-Only Perturbation

The full Hamming ball over the function table of $(A, \theta)$ is the union of two disjoint perturbation classes: perturbations to the wiring $A$, and perturbations to the dynamics $\theta$. The latter produce arbitrary Boolean functions that are not, in general, drawn from the gate library $\mathcal{L}$. The class is therefore large, biologically unconstrained, and structurally uninformative.

The protocol fixes the dynamics $\theta_0$ and perturbs only the wiring. The justification has three parts:

1. **Structural interpretability.** A change of one entry of $A$ has a unique semantic content: a regulatory edge is added, removed, or rewired. A change of one entry of a function table has no comparable semantic content; it produces an arbitrary Boolean function unrelated to the gate library.
2. **CausalBool alignment.** The CausalBool compressed representation (decimals, summandos) is itself a separation of wiring from logic. The decimal part encodes the wiring; the summandos encode the gate. A connectivity-only perturbation is a perturbation within the language of the representation, and the CausalBool loss function is well aligned with the perturbation metric.
3. **Biological and computational realism.** In gene regulatory networks, mutations that change regulatory wiring are more frequent and less deleterious than mutations that change the biochemical function of a regulator. The connectivity-only class is the perturbation regime in which the genetic-network application of CausalBool already operates.

The Hamming ball on the function table is therefore rejected as the laboratory's perturbation class. The connectivity ball $\mathcal{P}_k(A_0)$ is adopted.

### 4.2 The Connectivity Ball

For a chosen graph distance $d_g$ (default: edit distance, with edge addition and removal weighted equally), define
$$\mathcal{P}_k(A_0) \;=\; \{A : d_g(A, A_0) \le k\}.$$
A perturbation $A' \in \mathcal{P}_k(A_0) \setminus \{A_0\}$ is a single connectivity perturbation if $d_g(A', A_0) = 1$. The catalogue is
$$\mathcal{C}_k(A_0, \theta_0) \;=\; \{\mu_{A, \theta_0} : A \in \mathcal{P}_k(A_0)\}.$$

For the initial exploration $k = 1$ is sufficient; the protocol specifies $k \in \{1, 2, 3\}$ as the default sweep. Larger $k$ is admitted by the protocol but is computed only after the small-$k$ results are inspected.

### 4.3 Constraints on $A_0$

To ensure the attractor structure is non-trivial and the catalogue is informative, $A_0$ is drawn from the set of adjacency matrices that satisfy:

- bounded in-degree (default: maximum in-degree 3),
- at least one cycle in the underlying graph (so that attractors are not all fixed points),
- at least 30% of nodes with in-degree 2 or higher (so that the gate library has multiple inputs to act on).

The dynamics $\theta_0$ is drawn from a default library $\mathcal{L}_0$ defined in Section 5.

## 5. The CausalBool Compressor

### 5.1 The Compressed Form

A repertoire $\mu$ is a probability distribution on $\{0, 1\}^N$ with finite support $\mathrm{supp}(\mu) \subseteq \{0, 1\}^N$. The CausalBool compressor encodes $\mu$ as a pair $(D, S)$ where

- $D \in \{0, 1\}^*$ is a binary string that encodes the support of $\mu$ (the attractor states);
- $S \in \{0, 1\}^*$ is a binary string that encodes the visit counts as a sum of summands (a rational reconstruction of the empirical frequencies).

The encoding is exact: decompression recovers $\mu$ without loss. The bit length of the encoding is the compressed length
$$L_{\mathrm{CB}}(\mu) \;=\; |D| + |S|.$$
By the invariance theorem, $L_{\mathrm{CB}}(\mu) \ge K(\mu) - O(1)$ for a universal constant depending only on the compressor. The compressed length is therefore a computable upper bound on the prefix Kolmogorov complexity of $\mu$.

The exact format of $(D, S)$ is defined by the existing CausalBool routines (`encode_decimal_summandos`, `decode_decimal_summandos`). This protocol does not redefine the encoding; it specifies that the encoding is reused.

### 5.2 The Gate Library

The default gate library for the protocol is
$$\mathcal{L}_0 \;=\; \{\mathbf{0}, \mathbf{1}, \mathrm{ID}, \mathrm{NOT}, \mathrm{AND}, \mathrm{OR}, \mathrm{MAJ}, \mathrm{XOR}\},$$
restricted to input arity $\le 3$. The library is intentionally small: it is the smallest set of gates that supports non-trivial Boolean computation and matches the gate distribution observed in CausalBool's genetic-network benchmarks. The exact list of admissible gates is recorded in a single source-of-truth file in the implementation; the protocol does not depend on the specific library beyond the requirement that $|\mathcal{L}_0| \ge 6$ and that at least one nonlinear gate is present.

## 6. The Protocol

The protocol is a sequence of nine stages. Each stage has a clearly specified input, output, and termination condition. The stages are designed to be executed in order, but stages 5 through 8 are independent and can be parallelised.

### Stage 1 — Configuration

Input: a chosen $(N, k, A_0, \theta_0, \mathcal{L}_0, C, s)$.

Output: a configuration record written to `doppel-Challenge/configs/<config_id>.json` containing the chosen values, a SHA-256 of the configuration, and a timestamp.

Procedure:

- Choose $N \in \{4, 5, 6, 7, 8, 10, 12, 16, 20\}$ (default sweep).
- Choose $k \in \{1, 2, 3\}$ (default sweep).
- Choose $C > 0$. The default is the median value of $D_{\mathrm{KL}}(\mu_A \| \mu_0)$ across $A \in \mathcal{P}_1(A_0)$.
- Choose $s$. The default is the indicator on a randomly chosen target attractor $T \subseteq \mathrm{supp}(\mu_0)$ with $|T| = 1$.
- Choose the gate library $\mathcal{L}_0$ (default as in Section 5.2).
- Record the configuration.

### Stage 2 — Base Network and Natural Repertoire

Input: the configuration record.

Output: $(A_0, \theta_0)$ and $\mu_0 = \mu_{A_0, \theta_0}$, written to `doppel-Challenge/catalogues/<config_id>/base/`.

Procedure:

- Sample $A_0$ from the constrained set defined in Section 4.3.
- Sample $\theta_0 \in \mathcal{L}_0^N$ uniformly.
- Compute $\mu_0$ using the existing CausalBool attractor-enumeration and visit-counting routines.
- Record $(A_0, \theta_0)$ and $\mu_0$.

### Stage 3 — Catalogue Enumeration

Input: $(A_0, \theta_0)$ and $k$.

Output: the catalogue $\mathcal{C}_k(A_0, \theta_0)$ as a set of pairs $(A, \mu_{A, \theta_0})$, written to `doppel-Challenge/catalogues/<config_id>/catalogue.jsonl`.

Procedure:

- Enumerate $\mathcal{P}_k(A_0)$ by graph distance.
- For each $A \in \mathcal{P}_k(A_0)$, recompute $\mu_{A, \theta_0}$ using the existing CausalBool attractor-enumeration and visit-counting routines.
- The recomputation is linear in the network size and constant in $k$ for fixed $N$, so the total cost of the catalogue is $O(|\mathcal{P}_k| \cdot N)$.
- Store each pair $(A, \mu_A)$ as a line in the JSONL file.

### Stage 4 — Loss Surface

Input: the catalogue and the loss function $s$.

Output: for each $(A, \mu_A) \in \mathcal{C}_k$, the expected loss
$$\ell(A) \;=\; \sum_{x \in \mathrm{supp}(\mu_A)} \mu_A(x) \, s(x),$$
written to `doppel-Challenge/catalogues/<config_id>/loss.jsonl`.

Procedure:

- For each $\mu_A$, sum $s(x) \mu_A(x)$ over $x$ in the support of $\mu_A$.
- The cost is linear in the support size, which is bounded by $2^N$ and typically much smaller.

### Stage 5 — Divergence Surface

Input: the catalogue and $\mu_0$.

Output: for each $(A, \mu_A) \in \mathcal{C}_k$, the divergence
$$D_{\mathrm{KL}}(\mu_A \| \mu_0) \;=\; \sum_{x \in \mathrm{supp}(\mu_A) \cap \mathrm{supp}(\mu_0)} \mu_A(x) \log \frac{\mu_A(x)}{\mu_0(x)},$$
written to `doppel-Challenge/catalogues/<config_id>/kl.jsonl`.

Procedure:

- For each $\mu_A$, intersect the support with $\mathrm{supp}(\mu_0)$. Pairs $(A, \mu_A)$ for which $\mathrm{supp}(\mu_A) \cap \mathrm{supp}(\mu_0) = \emptyset$ are flagged with `support_disjoint = true` and the divergence is undefined.
- The cost is linear in the support size.

### Stage 6 — Support Distance

Input: the catalogue and $\mu_0$.

Output: for each $(A, \mu_A) \in \mathcal{C}_k$, the support distance
$$\Delta(\mu_A, \mu_0) \;=\; 1 - \frac{|\mathrm{supp}(\mu_A) \cap \mathrm{supp}(\mu_0)|}{|\mathrm{supp}(\mu_A) \cup \mathrm{supp}(\mu_0)|},$$
the Jaccard distance between the two supports, written to `doppel-Challenge/catalogues/<config_id>/support.jsonl`.

Procedure:

- For each $\mu_A$, compute the Jaccard index and the distance.
- The cost is linear in the support size.

### Stage 7 — Compressed Length and NCD

Input: the catalogue.

Output: for each $(A, \mu_A) \in \mathcal{C}_k$, the compressed length $L_{\mathrm{CB}}(\mu_A)$ and the normalised compression distance
$$\mathrm{NCD}(\mu_A, \mu_0) \;=\; \frac{L_{\mathrm{CB}}(\mu_A \mu_0) - \min(L_{\mathrm{CB}}(\mu_A), L_{\mathrm{CB}}(\mu_0))}{\max(L_{\mathrm{CB}}(\mu_A), L_{\mathrm{CB}}(\mu_0))},$$
where $\mu_A \mu_0$ denotes the concatenation of the two repertoires in a fixed encoding, written to `doppel-Challenge/catalogues/<config_id>/ncd.jsonl`.

Procedure:

- For each $\mu_A$, compute $L_{\mathrm{CB}}(\mu_A)$ using the existing CausalBool compressor.
- Concatenate $\mu_A$ and $\mu_0$ in a fixed order, compute the compressed length $L_{\mathrm{CB}}(\mu_A \mu_0)$.
- Compute the NCD.
- The cost is dominated by the compressor; both lengths are computable in time proportional to the support size.

### Stage 8 — Joint Statistics

Input: the outputs of Stages 4 through 7.

Output: a tabular record keyed by $(A, \mu_A)$, containing $(\ell, D_{\mathrm{KL}}, \Delta, L_{\mathrm{CB}}, \mathrm{NCD}, \mathrm{support\_disjoint})$, written to `doppel-Challenge/catalogues/<config_id>/joint.jsonl`.

Procedure:

- Join the four per-perturbation records on $A$.
- The result is the full statistic record for the catalogue.

### Stage 9 — Sweep and Aggregation

Input: a set of configuration IDs.

Output: aggregated statistics over the sweep, written to `doppel-Challenge/aggregated/<sweep_id>/`.

Procedure:

- For each configuration in the sweep, load the joint record.
- Aggregate by $(N, k, \mathrm{base\_graph\_class})$, where $\mathrm{base\_graph\_class}$ is a coarse equivalence class of $A_0$ (e.g. average in-degree, cycle count, modular structure).
- Record the joint distribution of $(\ell, D_{\mathrm{KL}}, \Delta, L_{\mathrm{CB}}, \mathrm{NCD})$ and the marginals.
- For each $(N, k)$, identify the catalogue element that maximises $\ell$ subject to $D_{\mathrm{KL}} \le C$. This is the laboratory's answer to the original phishing problem for that configuration.

## 7. The Loss Function $s$

The defender's loss function is exogenous to the laboratory. The protocol admits three canonical choices and one default:

1. **Indicator on a target set** (default): $s(x) = \mathbf{1}[x \in T]$ for a target set $T \subseteq \{0, 1\}^N$ with $|T| = 1$. The attacker wants to maximise the probability mass on a specific attractor. The target $T$ is chosen as a uniformly random element of $\mathrm{supp}(\mu_0)$.
2. **Linear functional**: $s(x) = w^\top x$ for a defender-chosen weight vector $w \in \mathbb{R}^N$. The attacker wants to shift the expected state in a particular direction. The default $w$ is a one-hot vector on a randomly chosen coordinate.
3. **Entropy-weighted**: $s(x) = -\log \mu_0(x)$. The attacker wants to drive the repertoire into low-probability regions of the natural one. This is the choice most closely tied to the Kolmogorov enrichment, because rare outputs are precisely the ones with high algorithmic information content.

The default is the indicator on a single target. The protocol allows the other two to be exercised in subsequent sweeps.

---

## 8. Mapping to the Original Problem

The mapping is the formal contract between the laboratory and the original phishing-detection problem. The contract is the following table.

| Phishing problem | Boolean network laboratory |
|---|---|
| Phrase set $T = \{t_1, \dots, t_n\}$ (fixed) | Attractor support $\mathrm{supp}(\mu) \subseteq \{0, 1\}^N$ (variable under perturbation) |
| Natural distribution $q$ over $T$ | Natural repertoire $\mu_0 = \mu_{A_0, \theta_0}$ |
| Attacker distribution $p$ over $T$ | Induced repertoire $\mu_A = \mu_{A, \theta_0}$ for $A \in \mathcal{P}_k(A_0)$ |
| Per-phrase payoff $s_i$ | Per-state loss $s(x)$ on $\{0, 1\}^N$ |
| Alarm quantity $\sum_i p_i \log(p_i/q_i)$ | Alarm quantity $D_{\mathrm{KL}}(\mu_A \| \mu_0)$ |
| Alarm threshold $C$ | Alarm threshold $C$ (same constant) |
| Detection budget $C$ | Detection budget $C$ |
| Expected payoff $\sum_i p_i s_i$ | Expected loss $\sum_x \mu_A(x) s(x)$ |
| Attacker choice space $\Delta_n$ | Attacker choice space $\mathcal{P}_k(A_0)$ (via $\Phi_{\theta_0}$) |
| Optimal $p$: exponential tilt $p^{(\lambda)}_i \propto q_i e^{\lambda s_i}$ | Optimal $A$: catalogue argmax of $\ell$ subject to $D_{\mathrm{KL}} \le C$ |

### 8.1 Structural Differences

The laboratory and the original problem differ in three substantive ways:

1. **Generative constraint.** The phishing attacker chooses $p$ directly. The laboratory attacker chooses a generative model $A$, which then induces $\mu_A$ through $\Phi_{\theta_0}$. The laboratory attacker's choice space is a strict subset of the simplex.
2. **Variable support.** The phishing problem has a fixed support $T$. The laboratory's induced repertoire can have a different support from $\mu_0$. The Kullback–Leibler alarm is well-defined only on the intersection; pairs with disjoint support are flagged and handled separately by the Jaccard distance and the compression distance.
3. **Discrete atomicity.** The phishing distribution $p$ is a point on the simplex. The laboratory repertoire is a discrete atomic distribution with at most $|\mathrm{supp}(\mu_0)|$ atoms. The laboratory problem is therefore a discrete combinatorial restriction of the original.

### 8.2 The Optimal Attacker in the Laboratory

For a fixed configuration $(N, k, A_0, \theta_0, C, s)$, the optimal adversarial network is
$$A^* \;=\; \arg\max_{A \in \mathcal{P}_k(A_0)} \; \ell(A) \quad \text{subject to} \quad D_{\mathrm{KL}}(\mu_A \| \mu_0) \le C,$$
where $\ell(A) = \sum_x \mu_A(x) s(x)$. The support-mismatch constraint is enforced by requiring that the support of $\mu_{A^*}$ intersects the support of $\mu_0$ (otherwise $D_{\mathrm{KL}}$ is undefined and the alarm is raised trivially).

This is the laboratory's answer to the original problem. The answer depends on the configuration; the protocol sweeps configurations to map the answer as a function of $N$, $k$, and the base graph class.

### 8.3 The Defender's Catalogue-Membership Test

In addition to the marginal alarm $D_{\mathrm{KL}}(\mu_A \| \mu_0) > C$, the defender can test catalogue membership: is the observed $\mu$ in $\mathcal{C}_k(A_0, \theta_0)$? The protocol precomputes the catalogue once and stores it. The defender's decision rule is

$$\mathcal{D}(\mu) \;=\; \begin{cases} \text{alarm}, & D_{\mathrm{KL}}(\mu \| \mu_0) > C \;\text{or}\; \mu \notin \mathcal{C}_k(A_0, \theta_0) \;\text{or}\; \mathrm{NCD}(\mu, \mu_0) > \eta, \\ \text{no alarm}, & \text{otherwise}, \end{cases}$$

where $\eta$ is a threshold on the normalised compression distance chosen by the defender. The three tests are complementary: the divergence alarm catches repertoire-level shifts, the catalogue-membership test catches structural anomalies, and the compression distance catches anomalies that share marginal structure but differ in algorithmic content.

### 8.4 The Defender's Mechanistic Advantage

The defender's mechanistic advantage is the difference in detection power between the marginal alarm and the catalogue-membership test, measured on a held-out set of perturbed networks. The protocol measures this advantage for each configuration and reports it as the primary quantitative result.

## 9. Theoretical Framework

### 9.1 Hypothesis-Testing Formulation

The protocol is a two-hypothesis test on the observed repertoire:

- $H_0$: the observed repertoire was generated by $(A_0, \theta_0)$.
- $H_1$: the observed repertoire was generated by some $(A, \theta_0)$ with $A \in \mathcal{P}_k(A_0)$.

The defender selects a test statistic $T(\mu)$ and a threshold; the alarm is $T(\mu) > \tau$. The marginal alarm uses $T = D_{\mathrm{KL}}(\mu \| \mu_0)$; the catalogue-membership test uses $T = \mathbf{1}[\mu \notin \mathcal{C}_k]$; the compression alarm uses $T = \mathrm{NCD}(\mu, \mu_0)$.

### 9.2 I-Projection and Sanov

The optimal attacker in the original problem is the I-projection of the argmax policy onto the divergence ball of radius $C$. In the laboratory, the same mathematical structure is preserved: the optimal adversarial network is the catalogue element closest in $I$-divergence to the worst-case (loss-maximising) catalogue element, restricted to the divergence ball.

Formally, if $\mu^* = \arg\max_{\mu \in \mathcal{C}_k} \sum_x \mu(x) s(x)$ is the unconstrained worst case, the optimal adversarial network is
$$A^* \;=\; \arg\min_{A \in \mathcal{P}_k(A_0)} D_{\mathrm{KL}}(\mu_A \| \mu^*) \quad \text{subject to} \quad D_{\mathrm{KL}}(\mu_A \| \mu_0) \le C.$$
This is the I-projection of $\mu^*$ onto the $D_{\mathrm{KL}}$-ball of radius $C$ around $\mu_0$, intersected with the reachable set $\mathcal{C}_k$.

### 9.3 Neyman–Pearson

The optimal defender test, in the Neyman–Pearson sense, is the likelihood-ratio test between $H_0$ and the worst-case $H_1$. For the laboratory, the likelihood-ratio is
$$\Lambda(\mu) \;=\; \frac{P(\mu \mid H_0)}{P(\mu \mid H_1)}.$$
For Boolean network repertoires, $P(\mu \mid H_i)$ is not defined in the usual sense — the model is deterministic. The Bayesian analog is the posterior over the generating network given the observed repertoire, which is exactly what the CausalBool deconvolution computes. The Neyman–Pearson test is therefore, in the laboratory, the catalogue-membership test in the limit where the catalogue exhausts the alternative.

### 9.4 Information Geometry

The space of repertoires is the probability simplex $\Delta_{2^N}$, a manifold with the Fisher information metric. The Kullback–Leibler divergence is the canonical divergence on this manifold. The reachable set $\mathcal{C}_k(A_0, \theta_0)$ is the image under $\Phi_{\theta_0}$ of a graph-distance ball in $\mathcal{A}_N$. The geometry of this image, embedded in $\Delta_{2^N}$, is the laboratory's central object of study.

Two open theoretical questions the laboratory is positioned to address:

1. **Lipschitz profile of $\Phi_{\theta_0}$.** How does $\| \mu_{A, \theta_0} - \mu_{A_0, \theta_0} \|$ scale with the graph distance $d_g(A, A_0)$? Is the profile uniform across $A_0$ and $\theta_0$, or does it concentrate on a small set of perturbations?
2. **Support-mismatch boundary.** What fraction of perturbations in $\mathcal{P}_k(A_0)$ change the support of the repertoire, as a function of $N$, $k$, and the base graph class? The boundary separates the regime in which $D_{\mathrm{KL}}$ is well-defined from the regime in which compression-based measures dominate.

### 9.5 Algorithmic Information Theory

The compressed length $L_{\mathrm{CB}}(\mu)$ is an upper bound on the prefix Kolmogorov complexity $K(\mu)$. The NCD is the Li–Bennett–Li–Vitányi universal similarity metric, which approximates the normalised information distance in the limit of an optimal compressor. The protocol's use of NCD is therefore not a heuristic; it is a computable proxy for the uncomputable normalised information distance, and it is universal in the precise sense of Li et al. 2004.

The CausalBool compressor is a particular compressor, not the optimal one. The bound $L_{\mathrm{CB}}(\mu) \ge K(\mu) - O(1)$ holds with a constant that depends on the compressor's description length. The constant is fixed across the sweep; the protocol reports the relative ordering of compressed lengths, not their absolute values.

## 10. Measurements

The protocol records the following statistics for every perturbation in the catalogue. All statistics are written in machine-readable form and accompanied by a header line specifying the configuration.

| Statistic | Symbol | Definition | Source |
|---|---|---|---|
| Expected loss | $\ell$ | $\sum_x \mu_A(x) s(x)$ | Stage 4 |
| Kullback–Leibler divergence | $D_{\mathrm{KL}}$ | $\sum_{x \in S} \mu_A(x) \log(\mu_A(x)/\mu_0(x))$ where $S = \mathrm{supp}(\mu_A) \cap \mathrm{supp}(\mu_0)$ | Stage 5 |
| Support disjointness | $b$ | $\mathbf{1}[S = \emptyset]$ | Stage 5 |
| Jaccard support distance | $\Delta$ | $1 - \lvert S\rvert / \lvert \mathrm{supp}(\mu_A) \cup \mathrm{supp}(\mu_0)\rvert$ | Stage 6 |
| CausalBool compressed length | $L_{\mathrm{CB}}$ | bit length of $(D, S)$ encoding of $\mu_A$ | Stage 7 |
| Compressed concatenation length | $L_{\mathrm{CB}}^{\cup}$ | bit length of $(D, S)$ encoding of $(\mu_A, \mu_0)$ | Stage 7 |
| Normalised compression distance | $\mathrm{NCD}$ | $(L_{\mathrm{CB}}^{\cup} - \min(L_{\mathrm{CB}}, L_{\mathrm{CB}}(\mu_0))) / \max(L_{\mathrm{CB}}, L_{\mathrm{CB}}(\mu_0))$ | Stage 7 |
| Graph distance | $d_g$ | $d_g(A, A_0)$ | Stage 8 |

The measurements are recorded in JSONL format. Each line is a self-contained record. The record schema is defined in `doppel-Challenge/doc/01-record-schema.md` (to be derived from this document).

## 11. Scaling Strategy

The protocol scales $N$ from small to moderate and records the cost, the catalogue size, and the runtime.

### 11.1 Small $N$ (4 to 8)

For $N \in \{4, 5, 6, 7, 8\}$, the catalogue is enumerated exhaustively. The number of perturbations is $|\mathcal{P}_k| \le \binom{N^2}{k}$. For $N=8$ and $k=3$, the catalogue is bounded by $\binom{64}{3} = 41{,}664$ elements. Each repertoire is computed in milliseconds. The total runtime is in minutes.

For $N=4$ and $k=1$, the catalogue has at most $16$ elements and the protocol is essentially instantaneous. The protocol therefore starts at $N=4$ to validate the implementation and the record schema before scaling up.

### 11.2 Moderate $N$ (10 to 20)

For $N \in \{10, 12, 16, 20\}$, exhaustive enumeration of $\mathcal{P}_k$ for $k \ge 2$ becomes expensive. The protocol specifies the following reductions:

- **Sample $\mathcal{P}_k$.** Draw $M$ samples (default $M = 1000$) uniformly at random from $\mathcal{P}_k$ and record the same statistics on the sample. The empirical distribution of the sample statistics is an estimator of the population distribution.
- **Stratify by $d_g$.** Stratify the sample by graph distance so that each $d_g \in \{0, 1, \dots, k\}$ is represented. The default is balanced stratification.
- **Estimate the optimal $A^*$.** The optimal adversarial network is estimated as the sample argmax of $\ell$ subject to $D_{\mathrm{KL}} \le C$. The protocol records the uncertainty in the estimate (bootstrap confidence interval over the sample).

The complexity reduction is linear in the sample size. The total runtime is dominated by the per-perturbation repertoire computation, which is linear in $N$ for fixed $k$ and $M$.

### 11.3 Computational Budget

The default computational budget is one node-hour per configuration, sufficient for $N \le 20$ and $k \le 3$ with the default sampling. The protocol records wall-clock time per stage and per configuration, written to `doppel-Challenge/catalogues/<config_id>/runtime.json`.

## 12. Expected Outcomes

The protocol produces, for each configuration, the joint distribution of $(\ell, D_{\mathrm{KL}}, \Delta, L_{\mathrm{CB}}, \mathrm{NCD})$ over the catalogue. From this distribution the following outcomes are derived.

### 12.1 The Optimal Adversarial Network

The sample argmax of $\ell$ subject to $D_{\mathrm{KL}} \le C$, with bootstrap uncertainty. This is the laboratory's answer to the original phishing problem for the configuration.

### 12.2 The Lipschitz Profile

The empirical relation between $d_g(A, A_0)$ and $D_{\mathrm{KL}}(\mu_A \| \mu_0)$. The profile is a function $\ell_{\theta_0}(d)$ that describes how rapidly the divergence grows with the graph distance. The protocol reports the profile for each $(\theta_0, A_0)$ and aggregates across the sweep.

### 12.3 The Support-Mismatch Boundary

The fraction of perturbations in $\mathcal{P}_k$ for which $\mathrm{supp}(\mu_A) \neq \mathrm{supp}(\mu_0)$, as a function of $N$ and $k$. The boundary is the regime in which the divergence alarm is well-defined; outside it, the compression-based measures dominate.

### 12.4 The Defender's Mechanistic Advantage

The difference in detection probability between the marginal alarm and the catalogue-membership test, measured on a held-out set of perturbations. The advantage is the primary quantitative result of the protocol.

### 12.5 The Compression-Distance Sensitivity

The correlation between $\mathrm{NCD}(\mu_A, \mu_0)$ and $D_{\mathrm{KL}}(\mu_A \| \mu_0)$, separately for support-preserving and support-changing perturbations. The correlation is the laboratory's answer to the question of when NCD adds information beyond KL.

### 12.6 Figures

The protocol specifies the following canonical figures, written to `doppel-Challenge/figures/<sweep_id>/`:

- `loss_vs_kl.png`: scatter plot of $\ell$ versus $D_{\mathrm{KL}}$ for the catalogue, with the constraint $D_{\mathrm{KL}} \le C$ overlaid.
- `lipschitz_profile.png`: $D_{\mathrm{KL}}$ versus $d_g$ for the catalogue, with the empirical envelope.
- `support_mismatch.png`: fraction of support-changing perturbations versus $N$, for each $k$.
- `ncd_vs_kl.png`: $\mathrm{NCD}$ versus $D_{\mathrm{KL}}$, coloured by support disjointness.
- `defender_advantage.png`: detection probability versus $C$, for the marginal alarm and the catalogue-membership test.
- `complexity_distribution.png`: histogram of $L_{\mathrm{CB}}$ over the catalogue, for each $N$.

The figures are publication-quality: 300 DPI, vector where possible, and accompanied by a CSV of the underlying data.

## 15. Open Questions

The following questions are open at the time of writing and are deliberately left for the experimental sweep to answer.

1. **Lipschitz concentration.** Does the divergence $D_{\mathrm{KL}}(\mu_A \| \mu_0)$ concentrate on a small set of perturbations in $\mathcal{P}_k(A_0)$, or is it uniformly distributed? The protocol measures the Gini coefficient of the divergence distribution over $\mathcal{P}_k$ and reports it.
2. **Support-mismatch rate.** What is the asymptotic rate at which the fraction of support-changing perturbations grows with $N$? The protocol fits a logistic curve to the empirical rate and reports the inflection point.
3. **Compression-distance redundancy.** Is NCD strictly more informative than $D_{\mathrm{KL}}$ on the support-preserving subset of perturbations? The protocol measures the conditional mutual information $I(\mathrm{NCD}; \ell \mid D_{\mathrm{KL}})$ and reports it.
4. **Defender's advantage ceiling.** Does the catalogue-membership test's detection probability saturate at 1 as $C$ decreases, or does it asymptote at a value strictly less than 1? The protocol measures the detection probability curve and reports the asymptote.
5. **Optimal attacker stability.** Is the optimal adversarial network $A^*$ stable under perturbation of the loss function $s$? The protocol measures the Jaccard distance between the argmax sets for two loss functions and reports it.

These are the questions the laboratory is designed to answer. The protocol records the data; the answers are derived in the post-experimental analysis.

That is good for checking machinery. It is **not** enough for the real experiment.

For the actual study, we should vary at least these structural families:

1. **Ring / near-ring**
   - baseline, low structural heterogeneity.

2. **Erdos-Renyi sparse directed graphs**
   - random wiring with controlled edge density.

3. **Fixed in-degree random graphs**
   - better control of logical comparability across nodes.

4. **Modular graphs**
   - several dense communities with sparse cross-links.

5. **Small-world graphs**
   - local structure plus a few long-range shortcuts.

6. **Hub-dominated / scale-heterogeneous graphs**
   - a few high-degree regulators.

7. **Cellular-automaton-like local graphs**
   - especially relevant given your earlier successful tests.

8. **Biological / literature-derived examples**
   - when available and small enough to validate.

So the correct design is:

- **Pilot phase**: one deterministic family, to verify correctness and timing.
- **Main phase**: several families, each with multiple seeds/instances per `N`.

In fact, this matters scientifically because the map from connectivity perturbation to behavioural change is almost certainly **family-dependent**. If we test only ring-like networks, we may confuse a property of that topology with a property of Boolean networks in general.

My recommendation is:

- keep the ring family as the **engineering baseline**,
- then add three main families first:
  1. sparse random with fixed mean in-degree,
  2. modular,
  3. hub-dominated.

That would already give us a much more credible experimental landscape without overengineering the first expansion.

So: **yes, we need much more variation**, but only after the pilot machinery is stable. The next implementation step should be to refactor `pilot_runner.py` so network generation is family-driven rather than ring-only.
