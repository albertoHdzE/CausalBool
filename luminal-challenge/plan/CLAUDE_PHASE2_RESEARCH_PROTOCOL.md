## 4. Product domains and proof obligations

At a new query epoch, freeze incumbent physical times/addresses x0, J0, selected operations W and original option/rank layout. Other operations/addresses remain fixed. LC is max(existing valid cycle lower bound, 1+maximum fixed issue time); LS is max(existing valid memory lower bound, maximum fixed allocated end address). Empty maxima are zero. For J0>0 and at least one result use LC=max(LC,1), LS=max(LS,1); treat a zero-objective incumbent as already unimprovable under nonnegative J.

Set Ccap=min(facts.horizon, floor((J0-1)/LS)); Scap=min(256, floor((J0-1)/LC)). If either is below its lower bound, the query has no strict improvement. For ordinary A2/A3 windows, selected time domains are incumbent±2 clipped to [0,Ccap-1]; address domains are ALL aligned bases with end<=Scap. Fixed decisions outside either cap make this window infeasible. Do not replace legal bases by greedy allocation choices. Domain.target is absent; accept/prune using C*S<Jbest. Caps derive from J0, stay frozen within the query and do not redefine codes when Jbest decreases. New best values only tighten branch-and-bound.

Prove the integer-cap lemma in the research note, explicitly scoped to the chosen original neighborhood/horizon and fixed decisions. On every exhaustible original fixture and every new qualified tiny fixture, compare retained strict improvements to an independent Cartesian/machine enumeration of the corresponding uncapped neighborhood. Demonstrate at least one artificial trade-off example covered by the product domain and omitted by the old target-rectangle UNION; if none is found, report that absence without inventing an example. A domain representation change may alter numerical indices; equivalence concerns normalized physical objects, not equality of integer codes across domains.

## 5. Sound propagation without changing the code map

Maintain a search-only copy of physical domains. se.Domain and its canonical options/layout remain immutable. Filter search alternatives by physical value; compute canonical ranks from the original unfiltered codec state. Never call the kth surviving value rank k. Final leaf encoding/decoding must round-trip through the unchanged codec.

Apply these rules to a fixed point in deterministic order (precedence edges by IDs, engine/cycle, then address pairs by producer IDs). Reaching any limit preserves UNKNOWN, never UNSAT:

1. Precedence: for t_v>=t_u+lag, remove u values larger than max(D_v)-lag and v values smaller than min(D_u)+lag; include data and pinned memory-order edges. Empty domain proves this branch impossible.
2. Engine issue capacity: singleton time domains occupy that engine/cycle. Too many proves inconsistency; a full cycle is removed from OTHER non-singleton domains on that engine. Count issues, not in-flight operations.
3. Allocation: only once ALL times are fixed, compute complete inclusive lifetimes using the original owner. For each overlapping-live pair, remove address values with no nonoverlapping support in the other domain, respecting widths/alignment. Apply to fixed and selected values. No greedy left packing, symmetry quotient or reduced-domain claim is authorized.
4. Product bound: LC=max(existing cycle lower bound, max_i(min(D_i)+1)). LS=max(widest result, max_v(min(A_v)+width_v), compulsory-live-width). To compute compulsory lifetime of v, let start_hi=max(D_producer)+latency and end_lo=max(min(D_producer)+latency, max_consumer min(D_consumer)). Only if start_hi<=end_lo is [start_hi,end_lo] guaranteed live. Sum widths over guaranteed intervals, take peak; alignment may strengthen feasibility but does not make this bound achievable. Prune if LC*LS>=Jbest. Prove each bound against every feasible completion on exhaustible cases, including unused results and consumers outside W.

Use existing machine/dependency/lifetime constants; do not restate them. Every deletion/prune has a reason type and enough local inputs to replay it. Retain full certificates for exhaustive/mutation tests; measured runs retain counts by rule, affected-domain hashes and an incremental certificate-stream digest, with a deterministic fixed-work replay artifact on each development family's first program. This is tested implementation plus mathematical arguments, not a formally verified proof of arbitrary-program correctness. Do not advertise certificate hashes alone as proof of soundness.

## 6. A4 neighborhoods and resumable traversal

At an incumbent epoch make five queues: existing windows_for(..., scratch_first=True) with radius 2; one queue for each k=4,8,16; and the small whole-program queue described below. For each k queue insert in this order: (a) k latest-issued operations (ID tie break); (b) a memory-pressure group defined next; (c) contiguous operation-ID windows of length k at starts 0,k,2k,... . Use radius 4 for k<=8 and radius 8 for k=16, all clipped by the product caps. Include shorter final windows. If the whole program has <=16 operations put its whole-program tuple with full [0,Ccap-1] time domains in the fifth queue, otherwise that queue is empty. Merge queues round-robin in the stated order, skipping exhausted queues, and deduplicate identical (selected-operation tuple, radius) pairs in first-seen order. Treat full-range as a separate radius tag. Thus larger neighborhoods are not starved behind every original small window. Larger programs get no implicit global completeness claim.

Memory group: compute complete incumbent lifetimes. Choose earliest cycle with maximum total live width. List producers of values live there by decreasing width, then decreasing allocated end address, then producer ID; append their consumer operation IDs ascending, then all remaining operation IDs ascending. Deduplicate in first-seen order and take first k. Store the final selected tuple sorted by operation ID, retaining its policy tag separately. This releases some consumers that determine lifetime endpoints; it does not assume those incumbent lifetimes remain fixed in a query.

Use the existing canonical order of decisions (times by operation ID, then addresses by producer order). Within a query, explore a heap of prefixes ordered by (discrepancy, product_lower_bound, negative_depth, canonical_rank_tuple). A discrepancy counts a chosen canonical rank>0, irrespective of its magnitude. Preferred rank zero is an ordering, not a constraint. Do not reorder variable identities or reinterpret state-dependent ranks. Maintain at most 4,096 queued prefixes in an active query; if exceeded, stop that query as UNKNOWN_FRONTIER_LIMIT with retained counts, not UNSAT. No beam dropping followed by completeness claims.

Round-robin the catalog with slices of at most 2 ms or 2,048 expanded nodes, whichever occurs first, retaining unfinished query state. Initialize lazily, at most eight resident queries. When a resident query completes or reaches a resource cap, fill its slot from the next catalog entry; each query has cumulative active-time allowance min(.1 seconds, overall budget remaining at its initialization). Sum measured construction/resume/validation durations for that query; time spent paused while other queries run is charged to the global deadline, not again to this query. The hard active deadline is min(global deadline, now plus remaining query active-time allowance); .002 seconds is a cooperative scheduling checkpoint, not an additional acceptance deadline. Pause/resume only at consistent state boundaries. A synchronous operation may overshoot a slice; account for it and yield afterward. A fully validated candidate within hard deadlines remains eligible even if the scheduling quantum elapsed. Domain construction and all resumes consume the query allowance, never reset it. In a pass, stop only on overall limit or completion/resource termination of every catalog query. If a validated improvement occurs, retain the new global incumbent, discard old epoch frontiers as superseded (not exhausted), and build a new catalog. Charge all work across epochs to the original deadline and aggregate limits. All cached rank interpretations are scoped to (program, domain, epoch) hashes.

On finite fixtures, disable wall limits and use sufficiently large explicit memory/work limits to prove equal feasible/improving object sets and minima against A2/oracle. Under actual limits, report how much search ended UNKNOWN. Returning a valid incumbent solves compilation; proving no better compilation requires exhaustive evidence in the declared domain.

## 7. A genuinely predictive schema ranker

Replace cube expansion as the learned candidate with a deterministic depth-3 binary decision tree over the ORIGINAL canonical index bits, fitted to all labeled training objects. A leaf denotes a cube: tested coordinates form its decimal anchor; untested coordinates are its free-coordinate mask. These schemata partition the entire bit universe and carry estimated quality, not feasibility guarantees. A coordinate free in a prediction leaf preserves that leaf's prediction only; it is not thereby irrelevant to actual feasibility or actual J.

Labels: 1 for training J at or below its ceil(0.1*n)-th sorted order statistic (ties included), 0 otherwise. At each node consider unused coordinates ascending; both children must contain >=4 training objects. Choose maximal reduction in weighted Gini impurity, compare exact rational values and tie-break by lower coordinate. Stop at depth 3, a pure node, no admissible split or gain<=0. Leaf score is (positive_count+1)/(count+2). No hyperparameter search. If fewer than 20 distinct validated training objects exist, record MODEL_UNAVAILABLE and continue the non-model search. Constant predictions are valid results, not grounds to remove a fixture.

A prediction ONLY orders proposals. It cannot prune, establish soundness, certify an improvement or bypass machine/case validation. The ranker sees training indices/products, not the hidden feasible set, oracle answers, test membership or test labels. Prove schema leaves are disjoint and cover the whole B-bit universe; that theorem concerns the predictor's representation, not correctness of predicted labels. Rank/bit meanings cannot be transferred across domain hashes. Training/model state is per query/fixture, never shared across unseen programs.

Common novel candidate pool for controlled learning tests: elite E from training; generate Hamming distance 1 then 2 neighbors, elite indices ascending, coordinate tuples lexicographic, taking the first 256 distinct indices outside the whole training set. Add up to 256 new indices from uniform B-bit draws with seed derived below, at most 8,192 draws (stop if universe exhausted). Deduplicate, sort final pool, and retain its hash. No feasibility filtering by an oracle. Learner/control arms get the SAME pool; selection never depends on test outcomes. Pool size/invalidity is reported, not hidden. All generation/fitting/scoring costs count toward wall time. Do not enumerate an exponential universe to construct the pool.

Orderings: tree = descending predicted probability then ascending code; ascending = code order; hamming = increasing minimum Hamming distance to E then code; shuffled_tree = same tree algorithm with training labels permuted while preserving class count; random = uniformly permuted pool with each of ten seeds. empirical_cover is the negative control proposing only already observed elite indices. Fixed-width integer Hamming computations and schema algebra must reuse available owners where applicable.

All semantic/seed keys use sha256 of compact sorted-key JSON, first 16 hexadecimal digits interpreted as an unsigned integer; never Python hash(). Pool seed is this function on [protocol_id, fixture_or_domain_hash, 2026092501]. Shuffled-label seed uses tag 2026092502. Ten random-order seeds are 2026092510–2026092519, combined with the fixture hash by the same function. Freeze every ordered pool/label-permutation digest. Model code never receives oracle/test maps; evaluator alone scores fully paid proposals.
